## 2. 광고주 질문지 (1부)
쉬운 말로 묻고, 모르면 "모르겠음"을 고르게 한다. 모르겠음은 AI가 추정해서 채우고 2부에 "추정"으로 표시한다.
첫 화면에 AI 사용 고지, 개인정보 수집 동의(필수), 포트폴리오 사용 동의(선택)를 둔다.

| 번호 | 질문 |
|---|---|
| 0 | 상호, 담당자 이름, 연락처 |
| 1 | 무엇을 파시나요 |
| 2 | 누구에게 팔고 싶으세요 |
| 3 | 이번 광고로 가장 얻고 싶은 것 (매출 / 문의·상담 / 회원가입 / 사이트·매장 방문 / 모르겠음) |
| 4 | 지금 가장 큰 고민 |
| 5 | 비슷한 경쟁 업체 (최대 3개, 로그인이 필요한 곳은 캡처 권장) |
| 6 | 우리가 더 나은 점 하나 |
| 7 | 꼭 넣을 말과 쓰면 안 되는 말 |
| 8 | 마음에 드는 광고와 싫은 광고 (선택) |
| 9 | 광고에 보여 줄 제품이 있나요 (있음 / 없음) |
| 10 | 사진과 로고가 있나요 |
| 11 | 어디에 광고하고 싶으세요 (인스타그램·페이스북 / 네이버 / 카카오 / 모르겠음) |

## 3. 아이디어 방향 표 (ad-ideation에 사용)

| 광고 목적 | 방향 1 | 방향 2 | 방향 3 |
|---|---|---|---|
| 매출 | 혜택 (가격, 구성, 사은품) | 비교 (경쟁·대안보다 나은 점) | 지금 사야 하는 이유 (한정, 시즌) |
| 문의·상담 | 고민 공감 | 믿을 근거 (후기, 경력, 수치) | 부담 없는 첫걸음 (무료 상담, 간단 신청) |
| 회원가입 | 가입하면 받는 것 | 쉬움·빠름 | 이미 쓰는 사람들 |
| 방문·인지 | 감성 (분위기, 공간) | 호기심 | 우리 가게다운 모습 |

- 목적이 애매하면 가장 가까운 것에 넣고 KPI 칸에 구체적으로 적는다.
- 단골 재방문처럼 대상만 다른 경우는 목적이 아니라 타깃으로 처리한다.
- "믿을 근거" 방향은 광고주 자료에 후기·수치가 없으면 "근거 없음"으로 표시하고 보완을 요청한다.
- 시안은 기본 2종이다. 같은 아이디어에서 메시지, 버튼 문구, 버튼 색만 다르게 만든 변형이며 그림과 배치는 같다.

## 4. 수정 기준
- 시안 변형(기본 2종)은 기본 패키지에 포함
- 글자, 색, 위치, 크기 조정, 이미지 교체는 포함 횟수 안에서 무료
- 콘셉트나 아이디어 자체를 바꾸는 것은 수정이 아니라 새 시안(추가 비용)
- 포함 횟수(1~3회)와 가격은 미정

## 5. 이미지 방침 (ad-image-router)

| 상황 | 방침 |
|---|---|
| 제품형, 사진 있음 | 원본에서 제품을 오려(누끼) 그대로 쓰고 배경·그림자·소품만 AI로 생성. 가장 안전 |
| 제품형, 원본 기반 재생성 | 원본을 참조로 AI가 다시 생성. 포장 글자·로고·무늬·색이 바뀌기 쉬워 원본과 나란히 비교 검수 필수. 다르면 폐기 |
| 제품형, 사진 없음 | 광고주에게 사진 요청. AI로 제품을 새로 그리지 않음 |
| 무형 (서비스·가게·금융 등) | 공간·사람·상황·상징 이미지를 AI로 생성하거나 실제 매장 사진 사용 |
| 무형 (병원) | 내부는 실제 사진 권장. 시술 장면, 전후 비교처럼 보이는 AI 이미지는 쓰지 않음 |

공통: 프롬프트에 "글자, 간판, 로고, 워터마크 넣지 말 것"을 고정 삽입. 한글 카피와 로고는 합성 단계에서 얹는다. 이미지 도구의 상업 이용 허용 여부를 확인하고 기록한다.

## 6. 합성 명세와 백엔드

도구에 중립적인 명세(`docs/compose_spec.example.json`)를 만들고 백엔드 어댑터가 실행한다.

```
선택된 아이디어 + 이미지 + 로고
        -> compose_spec.json
        -> [HTML 렌더(Playwright)] / [Figma 플러그인] / [Figma MCP: Claude Code 개발용] / [Canva: 별도 확인]
        -> 매체별 PNG/JPG + 편집 링크
        -> ad-qa (PNG만 보고 검수)
```

공통 동작: 템플릿에서 새 작업 만들기, 문구 채우기, 이미지 삽입, 누끼, 사이즈 변환, 내보내기, 편집 링크 반환.
백엔드가 지원하지 않는 동작은 `references/capabilities.md`에 "미지원"으로 적고 (1) 공통 스크립트로 대체하거나 (2) 게이트 2에서 사람이 처리한다.

- 시안 A/B는 반드시 같은 백엔드로 만든다 (레이아웃이 달라지므로).
- 도구 비교(비교 모드)는 내부 의사결정용이며 광고주에게 보여 주지 않는다. 초기 시험에서만 켠다.
- 비교 평가 항목: 한글 폰트, 줄바꿈·자간, 이미지 위치, 사이즈 3종, 편집 용이성.

## 8. 화면 구성

내부 콘솔 (AE·디자이너용)
- 왼쪽: 9단계 진행 표시줄 (게이트 2곳 강조)
- 본문: 현재 단계 산출물 (브리프 표와 출처 태그, 아이디어 카드, 이미지 갤러리, 합성 미리보기, 검수 체크리스트)
- 하단: 남은 확정 항목 수, 승인 버튼(화면당 하나), 수정 요청
- 비교 모드: 두 백엔드 결과를 나란히 놓고 항목별 평가 후 하나를 선택

광고주 화면 (모바일 기준)
- 질문지: 한 화면 한 질문, 진행률, 쉬운 말, "모르겠음", 첫 화면에 AI 고지와 동의
- 시안 선택: 시안 A/B 나란히, 차이는 문구와 버튼뿐이라는 설명, 확정 또는 수정 요청, 남은 수정 횟수

## 9. 웹 배포 구조

구성: 사용자 브라우저 / 서비스 서버(웹 앱·인증, 에이전트 워커, 합성 엔진) / 외부 API(Anthropic, 이미지 모델, Figma REST) / 암호화 저장소.

BYOK
- 키는 서버에서 암호화 저장(KMS 등 봉투 암호화), 화면에는 마지막 4자리만 표시, 브라우저로 반환하지 않는다.
- 작업 실행 시 워커에서만 복호화하고 로그·오류 메시지에서 마스킹한다.
- 입력 직후 가벼운 호출로 유효성을 검증하고, 삭제·교체·계정 삭제 시 파기한다.
- Anthropic 키와 이미지 모델 키를 따로 받는다.
- 케이스별 예상 비용을 표시하고 단계별 상한을 둔다. 지출 한도가 있는 전용 키를 만들도록 안내한다.

Figma
- OAuth 앱을 등록하고 사용자별로 인증을 받는다. 최소 범위(file_content:read)만 요청한다.
- 읽기: 템플릿 프레임, 로고·브랜드 자산, 프레임 이미지 렌더.
- 쓰기: REST API로 불가. 편집 인계가 필요하면 Figma 플러그인(사용자가 열어 둔 파일에서 실행)을 별도 개발한다.
- 리프레시 토큰은 암호화 저장하고 연결 해제 기능을 제공한다.

서비스 운영
- 사용자별 케이스 폴더·이미지·토큰 격리, 파일은 서명된 URL로만 제공
- 합성 엔진과 스크립트는 격리된 컨테이너에서 실행, 에이전트 도구는 허용 목록으로 제한
- 광고주가 올린 파일과 외부 페이지의 내용은 데이터로만 다루고 지시문으로 취급하지 않는다
- 개인정보(상호·담당자·연락처) 보관 기간과 처리방침 확정 필요 (현재 문서에서 "○년, 미정")
- 동의 문구에 외부 모델 API와 디자인 도구로 자료가 전송된다는 내용 포함
