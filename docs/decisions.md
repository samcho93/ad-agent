# 결정 기록 (2026-11-09 기준)

## 확정

| 결정 | 이유 |
|---|---|
| 사람 승인 게이트 2곳 (아이디어 선택, 최종 검수) | 문서 원칙: AI 결과를 그대로 내보내지 않는다. 방향을 가장 싼 시점에 잠그고, 법적·신뢰 문제가 걸린 납품 전에 사람이 확인 |
| 도구 중립적 합성 명세 + 백엔드 어댑터 | Figma/Canva/HTML 중 교체·비교가 쉬워진다 |
| 검수는 결과 PNG만 보고 별도 에이전트가 수행 | 백엔드와 무관한 기준, 자기 채점 방지 |
| 웹 배포 시 합성 기본 엔진은 서버 HTML 렌더 | Figma 쓰기가 서버에서 불가 (아래 참고) |
| BYOK: 사용자 키를 서버에 암호화 저장 | 비용을 사용자에게 귀속, 서버 측 장시간 작업 지원 |
| 도구 비교(비교 모드)는 내부용, 시안 A/B는 같은 백엔드 | 광고주에게 일관된 결과 제공 |

## 미정 (임의로 정하지 말고 질문할 것)
- 수정 포함 횟수 (1~3회)와 가격
- 개인정보 보관 기간 (납품 후 ○년)
- 이미지 생성 모델 (제품 형태 유지력, 상업 이용 허용 여부 기준)
- 합성 기본 백엔드를 운영 단계에서 무엇으로 할지 (비교 시험 결과로 결정)
- 심의 업종별 규정 (시작 전 확인 필요), 심의 소요 시간(평균 1~2주는 추정)
- 처리 시간 절감 효과: 문서에 "측정 예정"으로 남아 있음 (검증되지 않음)

## Figma 연동 제약 (조사 결과)
- 공식 원격 MCP 서버는 카탈로그에 등재된 클라이언트만 연결 가능. 직접 만든 OAuth 앱은 `mcp:connect` 범위를 받을 수 없고 개인 액세스 토큰도 거부됨.
  - https://help.figma.com/hc/en-us/articles/39216419318551
  - https://www.scalekit.com/blog/figma-mcp-vs-api
- REST API는 읽기 중심이며 노드를 생성·수정하지 못함. 코멘트, 변수, dev resource는 쓰기 가능.
  - https://developers.figma.com/llms.txt
- 플러그인 API는 사용자가 연 현재 파일만 읽고 편집 가능.
  - https://developers.figma.com/compare-apis
- 캔버스 쓰기(원격 서버)는 베타이며 무료 기간 후 사용량 과금 예정. 초안 밖 파일에 쓰려면 Full 시트 필요.
  - https://eseospace.com/blog/figma-mcp-server/
- Claude 앱과 Claude Code에서는 Figma 커넥터 쓰기를 쓸 수 있으므로 개발·시험용 백엔드로는 유효.
  - 설치: `claude plugin install figma@claude-plugins-official` 또는 `claude mcp add --transport http figma https://mcp.figma.com/mcp`

## Canva 참고
- 공식 원격 MCP: https://mcp.canva.com/mcp. 디자인 생성·편집, 내보내기, 리사이즈(유료 플랜), 이미지 생성, 배경 제거 도구가 있음.
- 모든 플랜에서 연결 가능하나 autofill과 브랜드 템플릿은 Enterprise 전용이라고 Canva가 안내. 다른 문서에는 Pro 이상으로 적힌 곳이 있어 계정에서 직접 확인 필요.
  - https://www.canva.com/en_in/ai-connector/
- Claude Code 연결: `claude mcp add --transport http canva https://mcp.canva.com/mcp`
- 웹 서비스에서 사용자별 OAuth로 연동 가능한지는 조사하지 않음.

## 확인 필요 사항
- 두 도구 모두 상업용 한글 폰트가 템플릿에 안정적으로 적용되는지 (시험 필요, 가장 중요)
- 한글 줄바꿈, 자간, 긴 문구 처리 품질
- Figma OAuth 앱을 공개 서비스로 배포할 때 앱 검토 필요 여부
- Anthropic API 키 지출 한도 설정 방법 안내 문구 (콘솔 기능 확인 후 작성)

## 비교 시험 방법
같은 템플릿 문구(헤드라인, 서브카피, CTA, 로고)와 같은 AI 이미지 한 장으로 각 도구에서 배너를 만들고 비교:
1. 한글 폰트와 줄바꿈 품질
2. 이미지 삽입 후 위치 안정성
3. 매체별 사이즈 3종을 만드는 데 걸리는 단계 수
4. 디자이너가 마지막에 손대는 시간
결과를 `references/capabilities.md`에 누적한다.

## 1단계 구현 메모 (2026-11-09)

### 구현하며 정한 것 (변경 가능)
- 스택: Next.js(App Router) + TypeScript, Anthropic TypeScript SDK. 케이스 저장은 파일시스템 `cases/`.
- LLM 백엔드: 지금은 Claude Code CLI(`claude -p --json-schema`, 로그인 계정 사용)로 진행 (사용자 결정, 2026-11-09). API 키 경로(`llm.backend: "api"`)도 남겨 두었고 웹 배포(BYOK)는 그쪽을 쓴다.
- LLM: `claude-opus-5-5`, effort `high`, 구조화된 출력(JSON 스키마). 안전 분류기 거절 시 서버 측 대체 모델(`fallbacks: "default"`) 사용. `config/settings.json`에서 변경.
- 브리프·아이디어 생성 모델에는 상호만 보내고 담당자 이름·연락처는 보내지 않는다.
- 브리프 → 아이디어 순서: 아이디어는 브리프 초안만 있어도 만들 수 있고, 확정한 값이 있으면 반영한다. 게이트 1은 확정 항목이 모두 처리되어야 통과한다.
  - 참고: ad-brief 스킬은 "사람이 확정하기 전에는 아이디어로 넘어가지 않는다"고 쓰여 있고, CLAUDE.md 흐름은 "브리프 → 아이디어 3안 → 게이트 1"이다. 둘을 함께 만족시키려고 위처럼 했다. 어느 쪽을 따를지 확인 필요.
- 브리프를 다시 만들면 이전 아이디어로는 게이트 1을 통과할 수 없다(아이디어 재생성 필요).
- 검증 오류가 있으면 1회 재생성. 사실 검사는 휴리스틱(숫자, 한글 수량 표현, 후기·수상 같은 단어, 금지어)이며 모든 지어낸 사실을 잡지는 못한다. 사람이 최종 확인한다.

### 새로 생긴 질문
- 게이트 1 승인자 확인: 1단계에는 로그인이 없어 승인자 이름을 입력값으로 받는다. 5단계 인증 전까지 이대로 둘지.
- 수정 범위가 "미정"인 채로 게이트 1 확정을 허용할지 (현재 허용, 값은 "미정"으로 기록됨).
- 경쟁사 캡처, 제품 사진·로고 파일 업로드는 1단계에 없다. 3단계(이미지)에서 받을지 질문지에서 받을지.
- 브리프 표에서 `[사용자 결정]`으로 확정된 행에 원래 태그(`[추정]` 등)를 함께 남긴다. 확정 후에는 추정 표시를 지울지.

### 실제 모델 시험 결과 (CLI, 가상 쿠키 가게, 2026-11-09)
- 2회 실행. 두 번 모두 모든 행에 출처 태그, "모르겠음" 항목(2·3·8·11번)에 [추정]이 붙었다. 지어낸 후기·수치는 없었다.
- 모델이 스스로 "'방부제를 넣지 않은'은 금지어 '무첨가'와 비슷하다", "'버터 100%'는 원재료 확인 후 사용"처럼 위험을 적었다.
- 1회차에 나온 검증 오류는 모두 검증기의 오탐이었다(방향 번호 "방향 1"을 숫자로 봄, 톤 설명 속 "'최고' 금지"를 금지어 사용으로 봄). 고치고 회귀 테스트를 넣었다.
- 1회 실행 비용 약 $0.4~0.5, 3~4분 (브리프·아이디어 각 1회 재시도 포함). 재시도 원인은 이제 llm_log.jsonl 에 남는다.
- 3번 "모르겠음"일 때 목적 추정이 실행마다 달랐다(방문·인지 / 문의·상담). 추정이라 사람이 게이트 1에서 확정하지만, 방향표가 바뀌므로 확정 후 아이디어를 다시 만들어야 한다.
