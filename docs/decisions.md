## Figma 연동 제약 (조사 결과)
- 공식 원격 MCP 서버는 카탈로그에 등재된 클라이언트만 연결 가능. 직접 만든 OAuth 앱은 `mcp:connect` 범위를 받을 수 없고 개인 액세스 토큰도 거부됨.
  - https://help.figma.com/hc/en-us/articles/39216419318551
  - https://www.scalekit.com/blog/figma-mcp-vs-api
- REST API는 읽기 중심이며 노드를 생성·수정하지 못함. 코멘트, 변수, dev resource는 쓰기 가능.
  - https://developers.figma.com/llms.txt
- 플러그인 API는 사용자가 연 현재 파일만 읽고 편집 가능.
  - https://developers.figma.com/compare-apis
- 캔버스 쓰기(원격 서버)는 베타이며 무료 기간 후 사용량 과금 예정. 초안 밖 파일에 쓰려면 Full 시트 필요.
  - https://eseospace.com/blog/figma-mcp-server/
- Claude 앱과 Claude Code에서는 Figma 커넥터 쓰기를 쓸 수 있으므로 개발·시험용 백엔드로는 유효.
  - 설치: `claude plugin install figma@claude-plugins-official` 또는 `claude mcp add --transport http figma https://mcp.figma.com/mcp`

- (해결, 2026-11-10) 저장소를 공개로 전환했다. 원본 PDF(docs/source)는 저장소 이력에서 지우고 로컬에만 둔다. 커밋 작성자는 GitHub noreply 주소로 바꿨다. 배포 주소: https://samcho93.github.io/ad-agent/
- (부분 확인, 2026-11-10) 배포 주소(https)에서 로컬 브리지(http://127.0.0.1) 연결 성공 (Claude 앱 내장 브라우저). 일반 Chrome에서는 '로컬 네트워크 접근' 권한을 한 번 물을 수 있어 사용자 확인 필요.
- 확인 필요: 브라우저에서 Figma REST API를 직접 부를 수 있는지(CORS). 안 되면 Figma도 2차(중계 필요)로 넘긴다.

## 다중 LLM 메모 (2026-11-10)
- 출력 형식: Anthropic은 구조화된 출력, OpenAI는 Responses API json_schema(strict), Gemini는 responseJsonSchema. 세 경우 모두 결과를 zod 스키마로 다시 검증하고, 태그·추정 표시·사실 검사는 코드가 붙인다.
- 추론 강도: OpenAI는 추론 모델(o 계열, gpt-5 계열)에만, Gemini는 3 계열(thinkingLevel)에만 보낸다. 그 밖의 모델은 기본값.
- Gemini 무료 등급은 입력이 Google 서비스 개선에 쓰일 수 있어 광고주 자료에는 유료 등급 키를 권한다고 설정 화면에 안내했다. (약관은 사용자가 직접 확인 필요)
- 확인 필요: OpenAI·Gemini 실제 키로 브리프·아이디어를 끝까지 생성해 본 적은 없다(잘못된 키로 연결·오류 처리만 확인). 모델마다 한국어 품질과 규칙 준수(근거 없음, 추정 표시)가 다를 수 있어 실제 키로 비교 시험이 필요하다.

## MVP 3단계(이미지) 메모 (2026-11-10)
- 흐름: 게이트 1 승인 → 자료 올리기(제품·매장 사진, 로고) → 이미지 방침(ad-image-router 경로, `04_images/policy.md`) → 프롬프트(LLM 초안 + 코드가 "글자·로고 금지", 빈 공간, 누끼 경로의 "제품 그리지 않기"를 고정으로 붙임) → Figma 프레임 가져오기 또는 직접 올리기 → 누끼 → 사람 검수 체크 → 고르기 → 이미지 확정(`approvals.md` 기록).
- 모든 이미지는 받는 즉시 `04_images/`에 저장하고 `04_images/log.jsonl`에 도구·프롬프트·Figma 위치·날짜·사람을 남긴다 (절대 규칙 7).
- 고르려면 "도구의 상업 이용 허용 확인"(누끼는 "원본 사진 사용 권한 확인")과 해당 검수 기준 체크가 모두 필요하다. 상업 이용 허용 여부는 도구 약관을 사람이 확인한다.
- Figma: api.figma.com 은 브라우저 요청(CORS)을 허용한다(실측, 2026-11-10). 렌더링 이미지 주소(S3)에서 브라우저로 받을 수 있는지는 실제 토큰으로 확인 필요. 막히면 "직접 올리기".
- 누끼(브라우저 안, 사진이 밖으로 나가지 않음): Transformers.js(Apache-2.0)
  - GPU(WebGPU, 셰이더당 저장 버퍼 17개 이상): BiRefNet-lite fp16 (onnx-community/BiRefNet_lite-ONNX, MIT, 115MB)
  - CPU: IS-Net 일반용 (imgly/isnet-general-onnx, MIT, 176MB). BiRefNet-lite는 CPU(WebAssembly)에서 메모리 부족(std::bad_alloc)으로 실패했다(실측).
  - 저장 버퍼 한도 16인 GPU에서 BiRefNet이 실패했다(실측). 한 번 고른 실행 방식은 페이지를 새로 열 때까지 바뀌지 않아, 처음에 GPU 한도를 보고 고른다. GPU가 실패하면 기억해 두고 새로고침 뒤 CPU로 한다.
  - 모델은 투명도만 계산하고 원본 픽셀은 그대로라 제품 글자·색은 바뀌지 않는다. 사람이 원본과 나란히 보고 확인한다.
  - AGPL인 @imgly/background-removal 라이브러리는 쓰지 않았다.
  - ONNX 런타임 파일은 사이트에서 직접 제공(외부 CDN 스크립트 금지). CSP에 'wasm-unsafe-eval'(WebAssembly 컴파일)과 Hugging Face 주소를 추가했다.
- 확인 필요: 실제 제품 사진(복잡한 배경, 반사·투명 포장)에서 누끼 품질. 시험은 단순한 시험용 그림으로만 했다.
- 확인 필요: GPU 경로(BiRefNet-lite)는 이 PC GPU 한도 때문에 실제로 돌려 보지 못했다.
- 순서: MVP 2단계(합성)는 아직 없다. 3단계에서 고른 배경·누끼 이미지가 2단계 합성의 입력이 된다.

## MVP 4단계(검수·게이트 2·납품) 메모 (2026-11-10)
- 검수(ad-qa, `.claude/skills/ad-qa/SKILL.md`)는 두 층이다 (사용자 결정: 규칙 검사 + LLM 이미지 검수).
  - 규칙 검사(코드, 비용 없음): PNG 헤더로 실제 크기 확인, 용량 표시(한도는 설정, 기본 "확인 필요"), 금지어·근거 없는 숫자·빈 문구·버튼 대비(합성 명세로 다시), 로고 파일이 있는데 로고가 없으면 경고, compose_spec_A/B 가 문구·버튼 말고 같은지.

  - 만든 쪽과 분리: 검수 프롬프트에는 결과 PNG, 얹은 문구, 로고 위치만 넣고 아이디어·이미지 프롬프트는 넣지 않는다.
  - 이미지 검수를 못 하면(규칙만, 실패, 예전 브리지) 게이트 2에 "이미지 안 AI 글자·로고 없음 (사람 확인)" 항목이 추가된다.
- Claude CLI 브리지 0.2.0: 이미지가 있으면 `--input-format stream-json --output-format stream-json --verbose` 로 이미지 블록을 넘긴다(실제 CLI로 확인). 응답에 `images_seen` 을 넣어, 이미지를 무시하는 예전 브리지의 결과는 쓰지 않는다. 요청 크기 한도 48MB, 이미지 12장·장당 8MB(base64).
