# MVP 개발 순서

범위를 줄여 단계적으로 만든다. 각 단계 끝에서 동작을 확인하고 승인을 받는다.

## 1단계: 질문지 -> 브리프 -> 아이디어 -> 게이트 1
- ad-intake: 질문 12개 수집, "모르겠음" 처리, 동의 기록 (01_intake.json)
- ad-brief: 출처 태그가 붙은 02_brief.md, "사람이 확정할 항목" 체크리스트
- ad-ideation: 방향표 기반 3안, 서로 겹치지 않게
- 게이트 1 화면: 아이디어 선택, 브리프 확정, 승인 기록 (approvals.md)
- 시험: 가상 광고주(동네 수제 쿠키 가게)로 "추정"과 태그 규칙이 지켜지는지 확인

## 2단계: 합성 엔진과 합성 명세
- compose_spec.json 스키마 확정 (docs/compose_spec.example.json 기준)
- 서버 HTML 렌더(Playwright) 합성 엔진: 문구, 이미지, 로고, 그라데이션, 매체별 사이즈 export
- 상업용 한글 폰트 선정과 줄바꿈 시험
- 템플릿 banner-square-v1 하나로 시작

## 3단계: 이미지 단계
- ad-image-router 연결: 제품 유무별 경로, 프롬프트 템플릿, 로그 저장
- 누끼 스크립트 (제품형, 사진 있음 경로)
- 이미지 모델 선택 (상업 이용 허용 확인), 모델 호출 래퍼

## 4단계: 검수와 게이트 2, 납품
- ad-qa: 자동 점검(이미지 내 글자·로고 생성 여부, 로고 위치, 문구 잘림, 규격·용량) + 사람 검수 체크리스트
- 게이트 2 화면, 시안 A/B 납품, 광고주 시안 선택 화면, 수정 횟수 추적
- 심의 업종 분기 (카피 사전 점검, 완성본 심의)

## 5단계: 웹 배포
- 사용자 인증, BYOK 저장·검증·삭제, 비용 표시와 상한
- 사용자별 격리, 서명된 URL, 컨테이너 격리 실행
- 개인정보 처리방침, 보관 기간, 동의 문구 확정

## 6단계: Figma 연동 (선택)
- Figma OAuth 앱 (file_content:read 만), 템플릿·브랜드 자산 읽기
- Figma 플러그인: 합성 명세를 받아 열려 있는 파일의 템플릿 프레임에 반영
- Claude Code 개발 중에는 Figma 커넥터 쓰기로 비교 시험 가능

## 미정 항목은 구현을 막지 않게 설정값으로 둔다
수정 포함 횟수, 가격, 보관 기간은 설정 파일의 값으로 분리하고 기본값에 "미정"을 표시한다.
