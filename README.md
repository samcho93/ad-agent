# 광고 시안(배너) 제작 에이전트 — 도움말

광고 배너 한 건을 만드는 일을 **"사람 4명이 약 3일"에서 "AI + 사람 1명"으로** 줄이기 위한 에이전트입니다.
AI가 초안(브리프, 아이디어, 이미지 프롬프트, 검수 의견)을 만들고, **사람이 고르고 확정합니다.** AI 결과를 그대로 내보내지 않습니다.

- 사이트 (Cloudflare Pages): https://ad-agent-4k9.pages.dev/ · 같은 앱 GitHub Pages: https://samcho93.github.io/ad-agent/
- 데스크톱 실행파일 (Windows): https://github.com/samcho93/ad-agent/releases/latest — `AdAgent-Setup-<버전>.exe`(설치) 또는 `AdAgent-Portable-<버전>.exe`(설치 없이 실행). 웹판과 같은 화면이며 데이터·키는 이 PC 안에만 저장됩니다.
- 광고주용 질문지: https://ad-agent-4k9.pages.dev/#/intake?mode=client
- 광고주용 시안 확인: https://ad-agent-4k9.pages.dev/#/proof
- 이 도움말은 저장소의 `README.md` 와 앱의 **도움말** 메뉴에 같은 내용으로 들어 있습니다.

## 1. 한눈에 보는 흐름

```
 광고주                   담당자(AE)·디자이너 + AI                                광고주
 ───────                  ─────────────────────────────────────────────────       ───────
 질문지 답 ──▶ 1 질문 수집 ─▶ 2 브리프 ─▶ 3 아이디어 3안 ─▶ [게이트 1]
                                                               │ 사람: 1안 선택, 브리프 확정
                                                               ▼
               4 이미지 ─▶ 5 합성(시안 A/B) ─▶ 6 검수 ─▶ [게이트 2]
                                                          │ 사람: 디자이너 최종 검수
                                                          ▼
               시안 확인 파일 ───────────────────────────────────────────▶ 확정 / 수정 요청
                    ◀──────────────────────────────────────────────── 답변 파일
               (심의 업종이면 완성본 심의) ─▶ 7 납품 ZIP
```

- **게이트 1·2**는 사람이 승인해야 다음 단계가 열립니다. 승인하면 앞 단계 결과가 잠깁니다.
- 수정 요청이 오면 합성(또는 이미지) 단계로 돌아가 **다시 검수 → 게이트 2 → 광고주 확인**을 거칩니다.
- 모든 승인은 `approvals.md`, 수정은 `revisions.md` 에 누가·언제·무엇을 했는지 남습니다.

## 2. 사용 방법

### 처음 한 번: 설정
1. **설정 → LLM 연결**에서 방식을 고릅니다.
   - 일반 사용자: 본인의 API 키 (Anthropic Claude / OpenAI / Google Gemini). **연결 확인**을 누르면 쓸 수 있는 모델 목록이 나오고, 거기서 모델을 고릅니다.
   - Claude Code 사용자: 이 PC에서 브리지를 실행하고 연결 코드를 넣습니다 (아래 "Claude CLI 브리지").
2. 필요하면 **Figma 개인 액세스 토큰**(Figma 설정 → 보안 탭)을 넣습니다. 프레임 링크로 이미지를 가져올 때만 씁니다.
3. 키는 비밀번호로 잠글 수 있습니다. 저장 위치는 브라우저 저장소 또는 (Chrome·Edge) PC 폴더 중 고릅니다.
4. (선택) **제품 종류별 규칙**: 제품 종류마다 강조색과 이유, 구도 메모, 헤드라인 최대 글자 수를 적어 둡니다 (예: 착즙기 → 신선함, 초록). 질문지 1번 답에 키워드가 있으면 아이디어·이미지 프롬프트에 참고로 들어가고, 합성의 첫 버튼 색과 헤드라인 길이 점검에 쓰입니다. 앱이 규칙 내용을 지어내지 않으며, 내보내기 파일로 팀과 나눕니다.

### 한 건 진행하기
| 단계 | 하는 일 | 남는 파일 |
|---|---|---|
| 1. 질문지 | 담당자가 직접 입력하거나, 광고주에게 질문지 링크를 보내 **답변 파일**을 받아 "케이스 → 광고주 답변 파일 가져오기". 모르면 "모르겠음"을 고르게 합니다 | `01_intake.json` |
| 2. 브리프 | **브리프 만들기** → AI 초안(출처 태그·추정 표시) → "사람이 확정할 항목"을 하나씩 확정 | `02_brief.json/.md` |
| 3. 아이디어 | **아이디어 만들기** → 광고 목적별 방향표에서 겹치지 않는 3안 | `03_ideas.json/.md` |
| 게이트 1 | 아이디어 1안 선택 + 확정 항목 모두 처리 + 승인자 이름 → **게이트 1 승인** | `approvals.md` |
| 4. 이미지 | 제품·매장 사진과 로고 올리기 → (사진을 기다리면 **제품 사진 상태: 광고주에게 요청 중**, 받으면 **사진 받음 → 누끼 경로로**) → **프롬프트 만들기** → 이미지 도구에 **제품 사진을 참조 이미지로 함께 넣어** 배경 만들기 → Figma 프레임 링크로 가져오기 / Ctrl+V 붙여넣기 / 직접 올리기 (**만든 방법** 기록) → **자동 누끼** → 검수 체크 → 고르기 → **이미지 확정** | `04_images/` |
| 5. 합성 | 시안 A/B를 1080x1080 · 1200x628 · 320x100 으로 미리 보며 문구(리드 문구, 엔터로 줄바꿈)·버튼 색·화살표·서브카피 색·제품·로고 위치 조정 → 점검(문구 잘림, **겹침 경고**, 금지어) 통과 → **PNG 6장 저장**. 균형·색·배치 같은 디자인 마무리는 사람이 합니다 | `05_compose/` |
| 6. 검수 | **검수 실행**(규칙 + LLM 이미지 검수, LLM 비용 있음) 또는 **규칙만 검사**(무료) → 오류는 고치거나 사유를 적고 넘기기 | `qa.json`, `qa_report.md` |
| 게이트 2 | 사람 확인 체크(오탈자, 로고 위치·크기, 광고주 요청 처리, 브랜드 톤, 디자인 마무리, 심의 업종이면 카피 사전 점검) → **게이트 2 승인** | `approvals.md` |
| 광고주 확인 | **시안 확인 파일 내려받기** → 시안 확인 주소(`#/proof`)와 함께 광고주에게 전달 → 광고주의 답변 파일을 **광고주 답변 파일 가져오기** | `delivery.json`, `revisions.md` |
| 변형 | 광고주가 고른 시안을 다른 매체·사이즈로 더 만들기 (질문지 11번 사이즈 자동 제안, 매체 가이드 메모) → PNG 저장 → 사람 확인 | `delivery.json` |
| 완성본 심의 | 심의 업종(의료·건강기능식품·금융 등)만: 심의 결과(통과/수정 필요, 날짜, 메모) 기록 | `approvals.md` |
| 7. 납품 | **납품 ZIP 내려받기**: 고른 시안의 사이즈별 PNG(추가 사이즈 포함), 합성 명세, 검수 보고서, 승인·수정 기록 | (ZIP 내려받기) |

- 다른 사람·다른 PC로 넘길 때는 **케이스 파일 내보내기/가져오기** (이미지 포함).
- 수정 종류: 글자·색·위치·크기 → 합성 단계로, 이미지 교체 → 이미지 단계로. **콘셉트 변경은 수정이 아니라 새 시안**(수정 횟수에 넣지 않고 별도 협의).
- 수정 요청이 오면 합성 화면 위에 요청 내용이 보이고, **AI 수정안 만들기**로 문구 후보와 색·위치·크기 조정값을 받을 수 있습니다. 고른 것만 반영되고(자동 변경 없음), 금지어·근거 없는 숫자·허용 범위는 코드가 다시 검사합니다. 이미지 교체는 사람이 합니다.
- "사람이 확정할 항목"의 개수는 AI 초안의 추정·검증 경고에 따라 초안마다 달라질 수 있습니다.
- 시안 A/B는 그림·배치가 같고 문구·버튼(과 리드 문구·서브카피 색)만 다릅니다. 메시지 차이를 비교하기 위해서입니다.

### 광고주가 하는 일 (휴대폰, 로그인 없음)
- **질문지**: 받은 링크에서 한 화면에 한 질문씩 답하고, 마지막에 답변 파일을 내려받아 담당자에게 보냅니다. 매체는 대표 매체 하나(사이즈·용량 한도는 알면 선택 입력)만 고릅니다. 첫 화면의 개인정보 안내는 아직 **초안**입니다(보관 기간 미정).
- **시안 확인**: 받은 시안 확인 파일을 `#/proof` 화면에서 열고, A/B 중 하나를 확정하거나 수정을 요청한 뒤 답변 파일을 담당자에게 보냅니다. 파일은 그 휴대폰 안에서만 열리고 어디에도 올라가지 않습니다.

## 3. 어떻게 구성되어 있나

### 3.1 서버 없는 정적 웹 앱
```
 사용자 브라우저 (GitHub Pages에서 받은 정적 앱)
 ├─ 화면 + 에이전트 로직 (React, TypeScript)
 ├─ 케이스 저장: IndexedDB 또는 사용자가 고른 PC 폴더
 ├─ 키 저장: 이 브라우저에만 (선택: 비밀번호 암호화 PBKDF2 + AES-GCM)
 │
 ├──▶ LLM: Anthropic / OpenAI / Gemini API (사용자 키로 직접 호출)
 ├──▶ 또는 이 PC의 Claude CLI 브리지 (http://127.0.0.1:8787)
 ├──▶ Figma REST API (프레임 PNG 가져오기, 선택)
 └──▶ Hugging Face (누끼 모델 파일을 처음 한 번 받음)
```
- **우리 서버가 없습니다.** 광고주 자료와 키는 사용자 PC·브라우저에만 있고, 사용자가 고른 LLM 회사로만 전송됩니다.
- 모델에는 상호와 질문지 답만 보내고 **담당자 이름·연락처는 보내지 않습니다.**
- 배포본에는 CSP(콘텐츠 보안 정책)가 들어가 외부 스크립트를 실행하지 않고, 허용한 주소로만 통신합니다.

### 3.2 LLM 연결 방식
| 방식 | 대상 | 특징 |
|---|---|---|
| Anthropic API 키 | 일반 사용자 | 구조화된 출력(JSON 스키마), adaptive thinking |
| OpenAI API 키 | 일반 사용자 | Responses API, json_schema strict |
| Gemini API 키 | 일반 사용자 | responseJsonSchema |
| Claude CLI 브리지 | Claude Code 사용자 | 본인 Claude Code 로그인으로 `claude -p` 실행. 이미지 검수 지원(0.2.0) |
| 가짜 모델 | 개발·시험 | `npm run dev:fake`, 키 없이 화면 시험 |

어느 방식이든 결과는 같은 zod 스키마로 다시 검증하고, 출처 태그·추정 표시·사실 검사는 **코드가** 붙입니다.

### 3.3 스킬 = 프롬프트의 단일 원본
`.claude/skills/` 의 SKILL.md 가 빌드할 때 그대로 프롬프트로 들어갑니다. Claude Code에서도 같은 스킬을 쓸 수 있습니다.

| 스킬 | 단계 | 하는 일 |
|---|---|---|
| `ad-intake` | 1 | 질문 12개(0~11번), "모르겠음", 동의 기록 |
| `ad-brief` | 2 | 2부 브리프 초안, 출처 태그, 사람이 확정할 항목 |
| `ad-ideation` | 3 | 광고 목적별 방향표에서 겹치지 않는 3안 |
| `ad-image-router` | 4 | 제품 유무·심의 여부로 이미지 경로, 글자·로고 없는 프롬프트, 검수 기준 |
| `ad-qa` | 6 | 결과 PNG만 보고 AI 글자·로고, 가독성, 제품 일치, 심의 위험 판정 |
| `ad-revise` | 수정 | 광고주 수정 요청을 읽고 문구 후보와 색·위치·크기 조정값을 제안 (적용은 사람) |

합성(5단계)은 LLM을 쓰지 않으므로 스킬이 아니라 코드(`src/core/compose.ts`, `src/render/`)로 만들었습니다.

### 3.4 절대 규칙을 코드로 지키는 방법
| 규칙 | 지키는 방법 |
|---|---|
| 광고주가 주지 않은 사실(후기, 수치, 수상)을 쓰지 않는다 | 질문지 답에 없는 숫자·수량·근거를 코드가 찾아 오류로 표시하고 1회 다시 생성, 남으면 사람 확정 항목으로 |
| AI 추정에는 "추정" 표시, 항목마다 출처 태그 | 모델은 내용만 쓰고 `[1부 답 n번]` `[AI 초안]` `[사용자 결정]` `[추정]` 은 코드가 붙임 |
| 이미지 안에 글자·로고를 AI로 만들지 않는다 | 프롬프트 끝에 "글자·로고 금지"를 코드가 고정으로 붙임, 문구·로고는 합성 단계에서 폰트·원본 파일로 얹음, 검수에서 다시 확인 |
| 제품 사진이 없으면 AI로 제품을 그리지 않는다 | "사진 없음" 경로는 프롬프트 생성을 막고 사진을 요청 |
| 심의 업종은 단계 추가 | 게이트 2에 카피 사전 점검 필수, 완성본 심의 통과 기록이 있어야 납품 |
| 키·토큰을 파일·로그에 남기지 않는다 | 키는 브라우저 저장소에만, 로그(`llm_log.jsonl`)에는 용도·모델·사용량·검증 결과만 |
| 생성 이미지는 즉시 저장하고 기록 | 가져오는 순간 `04_images/` 에 저장, 도구·프롬프트·날짜·사람을 `log.jsonl` 에 |

### 3.5 이미지와 합성
- **이미지는 Figma에서 만듭니다** (디자이너 작업 또는 Figma AI). 앱은 프롬프트를 쓰고, Figma 프레임을 REST API로 가져오거나 붙여넣기·직접 올리기로 받습니다.
- **누끼는 브라우저 안에서** 합니다 (Transformers.js). GPU가 충분하면 BiRefNet-lite, 아니면 CPU로 IS-Net (둘 다 MIT). 사진이 PC 밖으로 나가지 않고, 제품 픽셀은 바꾸지 않고 투명도만 계산합니다.
- **합성은 브라우저 캔버스**에서 Pretendard 폰트(SIL OFL 1.1)로 문구를 그립니다. 시안 A/B는 그림·배치를 한 곳에 두어 구조상 같고, 문구·버튼 문구·버튼 색만 다릅니다. 한글은 어절 단위로 줄을 바꾸고, 영역을 넘치면 저장을 막습니다.
- 정해진 템플릿으로 배치하므로 **제품과 문구의 균형, 색을 고르는 이유 같은 디자인 판단은 사람이 마무리**합니다. 앱은 겹침(제품의 보이는 부분이 문구·버튼·로고를 가림)을 알려 주고, 버튼 색이 어디서 왔는지(제품 종류 규칙 / 기본값) 보여 줍니다.
- 다른 사이즈(변형 단계)는 비율에 따라 띠형·가로형·정사각/세로형 배치 중 가까운 것을 키우거나 줄여 만듭니다.
- 합성 결과와 함께 도구 중립 명세(`compose_spec_A/B.json`)를 남겨, 나중에 다른 도구(Figma 플러그인 등)로 같은 시안을 만들 수 있게 했습니다.

### 3.6 검수 (만든 쪽과 분리)
- **규칙 검사**(코드, 무료): PNG 실제 크기, 용량, 금지어, 근거 없는 숫자, 버튼 대비, 로고 유무, A/B 차이.
- **이미지 검수**(LLM): 시안 PNG 6장과 원본 제품 사진만 보고 판정합니다. 아이디어나 이미지 프롬프트는 넘기지 않아, 만든 쪽의 의도와 분리합니다. 모델은 판정과 근거만 내고, 오류·경고 구분은 코드가 합니다.
- 이미지 검수를 못 하면(규칙만 실행, 실패, 예전 브리지) 게이트 2에 "사람이 직접 확인" 항목이 추가됩니다.

### 3.7 케이스 파일
```
{상호}_{날짜}/
  00_case.json         상태, 심의 추가 단계
  01_intake.json       1부 답, 동의 기록
  02_brief.json/.md    2부 브리프 (출처 태그)
  03_ideas.json/.md    아이디어 3안, 고른 안
  04_images/           이미지 원본, images.json, policy.md, log.jsonl
  assets/              광고주 사진·로고 원본
  05_compose/          compose.json, compose_spec_A/B.json, A/B × 사이즈별 PNG, log.jsonl
  qa.json, qa_report.md  검수 결과·보고서
  delivery.json        시안 확인 파일 발송·답변·심의·납품 기록
  approvals.md         게이트·승인 기록
  revisions.md         수정 기록

```
상태 순서: 질문 수집 → 브리프 초안 → 아이디어 초안 → 게이트 1 승인 → 이미지 확정 → 합성 완료 → 검수 완료 → 게이트 2 통과 → 광고주 확정 → 납품 완료.

## 4. 어떻게 만들었나

### 4.1 출발점
업무 가이드, 기존 방식과 AI 방식 비교, 제품 유무별 사례 문서(원본은 공개 저장소에 올리지 않음)를 바탕으로 다음 문서를 먼저 정리했습니다.
- `CLAUDE.md`: 목적, 절대 규칙, 작업 방식 (Claude Code가 매번 먼저 읽는 파일)
- `docs/architecture.md`: 파이프라인, 게이트, 스킬, 합성 명세
- `docs/decisions.md`: 확정한 결정, 미정 항목, 확인할 것 (구현하며 날짜별 메모 추가)
- `docs/mvp-plan.md`: 개발 순서
- 스킬 `ad-brief`, `ad-image-router` (처음부터 주어짐) → 나머지 스킬은 문서 설명대로 추가

### 4.2 Claude Code로 단계별 개발
모든 단계를 같은 방식으로 진행했습니다: **계획 제시 → 사용자 승인 → 구현 → 단위 테스트 → 가짜 모델로 브라우저 확인 → (가능하면) 실제 모델 시험 → 커밋·배포.** 미정 항목은 임의로 정하지 않고 질문하거나 `decisions.md` 에 남겼습니다.

| 순서 | 내용 |
|---|---|
| 1 | MVP 1단계: 질문지 → 브리프 → 아이디어 → 게이트 1 (처음에는 Next.js 서버 앱) |
| 2 | 구조 개편: 서버 없는 정적 앱 + GitHub Pages, 키·데이터는 사용자 PC에만, Claude CLI 브리지 |
| 3 | LLM 연결 추가: OpenAI, Gemini (사용자 키) |
| 4 | MVP 3단계: 이미지 (Figma 연동, 붙여넣기, 브라우저 누끼) |
| 5 | MVP 2단계: 합성 (캔버스, Pretendard, 사이즈 3종, 점검) |
| 6 | MVP 4단계: 검수, 게이트 2, 광고주 시안 확인, 심의, 납품 ZIP |
| 7 | Cloudflare Pages 배포, SamStudy 허브 등록 |
| 8 | 테스트 후기 반영: 사진 요청 중 상태, 매체 질문·변형 단계, 개인정보 안내 초안, 겹침 경고·점검 범위·참조 생성 안내·만든 방법 기록, 제품 종류별 규칙 |
| 9 | 수정 요청 AI 수정안 (문구 후보·조정값 제안, 사람이 골라 적용) |

### 4.3 주요 결정과 이유
| 결정 | 이유 |
|---|---|
| 서버 없는 정적 앱 (처음 계획한 서버 + 키 암호화 저장 대신) | 여러 사용자가 각자 키와 데이터를 자기 PC에만 두고, 설치 없이 쓰게 하려고. 중계 서버가 필요한 기능은 2차로 미룸 |
| LLM 출력은 JSON 스키마로만, 태그는 코드가 | 모델이 규칙(추정 표시, 근거 없음)을 빠뜨려도 결과가 규칙을 지키게 |
| 이미지는 Figma에서 (앱 안 이미지 생성 대신) | 사용자 결정. 디자이너가 쓰는 도구에서 만들고 앱은 프롬프트·기록·검수를 맡음 |
| 브라우저 누끼, MIT 모델만 | 사진을 밖으로 보내지 않고, AGPL 라이브러리를 피하려고 |
| 합성은 브라우저 캔버스 (서버 Playwright 대신) | 정적 앱 구조에 맞춤. 같은 명세(compose_spec)로 다른 엔진을 붙일 수 있게 둠 |
| 광고주 확인은 파일 주고받기 | 서버 없이 로그인 없이 동작하게 (사용자 결정) |
| 검수는 규칙 + LLM 이미지 검수 | 코드로 볼 수 있는 것은 코드로, 눈으로 봐야 하는 것은 LLM 1차 + 사람 최종 (사용자 결정) |

### 4.4 기술과 라이선스
- Vite 6, React 19, TypeScript, zod (스키마 검증), vitest (테스트)
- `@anthropic-ai/sdk`, `openai`, `@google/genai` (각 회사 공식 SDK, 쓰는 것만 나중에 불러옴)
- `@huggingface/transformers` (누끼, Apache-2.0), 모델 BiRefNet-lite·IS-Net (MIT)
- `fflate` (ZIP, MIT), `marked` (도움말 표시, MIT), Pretendard 폰트 (SIL OFL 1.1, `public/licenses/`)

### 4.5 시험
- `npm test`: API를 부르지 않는 단위·흐름 테스트 (가상 광고주 "동네 수제 쿠키 가게"). 규칙 위반을 일부러 넣은 응답 → 검증 오류 → 재생성, 게이트 잠금, 수정 → 재검수 → 납품까지.
- `npm run dev:fake`: 가짜 모델로 처음부터 납품까지 화면 확인.
- 실제 모델: Claude CLI 브리지로 브리프·아이디어 생성과 이미지 입력을 확인했습니다.

## 5. 정하지 않은 것과 한계
- **미정** (설정값으로 두고 임의로 정하지 않음): 수정 포함 횟수(1~3회)와 가격, 개인정보 보관 기간(계약·결제 / 연락처)과 동의 문구 확정, 심의 수정을 수정 횟수에 넣을지, 매체별 파일 용량 한도, 업종별 심의 규정, 제품 종류별 규칙의 내용.
- **아직 확인하지 않음**: OpenAI·Gemini 실제 키로 끝까지 생성, 실제 키로 이미지 검수 품질과 비용(한 번에 이미지 6~7장), 실제 제품 사진의 누끼 품질, GPU 누끼 경로, 실제 휴대폰에서 시안 확인 파일 주고받기.
- **2차로 미룸**: 중계 서버가 필요한 기능(예: 광고주 링크만으로 주고받기), Figma 플러그인(합성 명세를 Figma 파일에 반영).
- 처리 시간 절감 효과는 아직 측정하지 않았습니다.

## 6. Claude CLI 브리지
Claude Code가 설치·로그인된 PC에서 (Node 18 이상, 의존성 없음):
```bash
node bridge/bridge.mjs
```
- 화면에 나오는 주소와 **연결 코드**를 웹 앱 설정에 넣습니다. 코드는 `~/.ad-agent-bridge.json` 에 저장됩니다 (`--new-code` 로 새로 만들기).
- 127.0.0.1 에서만 열리고, 허용된 웹 주소(Cloudflare Pages, GitHub Pages, irodmas.com, localhost, 데스크톱 실행파일 `app://ad-agent`)에서 온 요청만 받습니다. 데스크톱 실행파일에서 쓰려면 브리지 0.2.2 이상이 필요합니다. 다른 주소에서 쓰려면 `--origin https://...`.
- 하는 일은 `claude -p --json-schema` 구조화 생성 하나뿐입니다(도구 없음). 검수 때는 시안 이미지도 함께 넘깁니다(0.2.0부터). 프롬프트와 이미지는 기록하지 않습니다.
- Chrome에서 처음 연결할 때 "로컬 네트워크 접근" 허용을 물을 수 있습니다.

## 7. 개발자용
```bash
npm install
npm run dev        # http://localhost:5173
npm run dev:fake   # 가짜 모델로 화면만 시험 (키 불필요)
npm test           # API 호출 없는 테스트
npm run typecheck
npm run build      # dist/ (배포본에는 CSP가 들어간다)
```
화면 제목 옆에 버전(`v0.6.1` 등)이 나옵니다. 마우스를 올리거나 도움말 목차 아래를 보면 `v<버전> · <빌드 시각> · <커밋>` 으로 지금 보고 있는 빌드를 알 수 있습니다 (빌드할 때마다 바뀜, `*` 는 커밋하지 않은 변경이 있는 빌드). 기능을 더해 배포할 때 `package.json` 의 버전을 올립니다.

배포는 두 곳입니다. 빌드는 상대 경로(`base: "./"`)라 어느 주소 아래에 올려도 동작합니다 (SamStudy 허브 `irodmas.com/<강좌>/` 포함).
- **Cloudflare Pages** (`wrangler.toml`, 프로젝트 `ad-agent`): `npm run deploy:cf` (= `vite build --mode cloudflare` 후 `wrangler pages deploy dist`). Pages 는 파일 하나가 25MiB 까지라, 누끼용 ONNX 런타임 wasm(25.6MiB)만 jsDelivr 의 같은 버전(바이트 동일)에서 받습니다.
- **GitHub Pages**: `main` 에 푸시하면 GitHub Actions(`.github/workflows/pages.yml`)가 테스트·빌드 후 올립니다.
- **데스크톱 실행파일 (Electron)**: `npm run dist:win` → `release/` 에 `AdAgent-Setup-<버전>.exe`(NSIS 설치판), `AdAgent-Portable-<버전>.exe`. 만든 파일은 GitHub Release(태그 `v<버전>`)에 올리고, SamStudy 허브에는 프로그램으로 등록합니다. `npm run electron` 은 빌드 후 바로 실행합니다.
  - `electron/main.cjs` 가 웹판과 같은 `dist/` 를 `app://ad-agent/` 주소로 띄웁니다 (IndexedDB·폴더 저장소·LLM API 호출이 웹 주소처럼 동작). 바깥 링크는 기본 브라우저로 엽니다.
  - 코드 서명은 하지 않아 처음 실행할 때 Windows SmartScreen 경고가 나올 수 있습니다 ("추가 정보 → 실행").

| 경로 | 내용 |
|---|---|
| `.claude/skills/` | 스킬 = 프롬프트의 단일 원본 (빌드에 텍스트로 들어감) |
| `src/core/` | 질문지·브리프·아이디어 스키마와 검증, 케이스 서비스(상태·게이트·잠금·내보내기), 이미지·합성·검수·납품 서비스 |
| `src/llm/` | 생성기(Anthropic·OpenAI·Gemini·브리지·가짜), 단계별 파이프라인(검증 실패 시 1회 재생성), 이미지 검수 |
| `src/render/` | 캔버스 합성 엔진, 폰트 |
| `src/integrations/` | Figma 프레임 가져오기, 브라우저 누끼 |
| `src/storage/` | 케이스 저장소(IndexedDB / PC 폴더 / 메모리), 설정·키 저장과 암호화 |
| `src/ui/` | 화면 (홈, 질문지, 케이스, 케이스 상세, 시안 확인, 설정, 도움말) |
| `bridge/bridge.mjs` | Claude CLI 브리지 (로컬 실행, 배포본에 포함되지 않음) |
| `config/settings.json` | 기본값과 미정 항목 |
| `tests/` | 테스트와 가상 광고주 질문지 |

문서: `CLAUDE.md`(Claude Code 작업 지침), `docs/architecture.md`, `docs/decisions.md`, `docs/mvp-plan.md`, `docs/compose_spec.example.json`.
