# 광고 시안(배너) 제작 에이전트

배경과 결정은 [CLAUDE.md](CLAUDE.md), [docs/architecture.md](docs/architecture.md), [docs/decisions.md](docs/decisions.md) 참고.

## 현재 범위: MVP 1·2·3·4단계
질문지 → 브리프 2부(AI 초안, 출처 태그) → 아이디어 3안 → 게이트 1(사람이 확정·선택·승인) → 이미지(방침, 프롬프트, Figma 가져오기·붙여넣기·직접 올리기, 브라우저 누끼, 검수 체크, 이미지 확정) → 합성(시안 A/B × 1080x1080·1200x628·320x100, Pretendard, 점검, PNG 저장) → 검수(규칙 + LLM 이미지 검수) → 게이트 2(디자이너 최종 검수) → 광고주 시안 확인(파일 주고받기) → (심의 업종) 완성본 심의 → 납품 ZIP. 배포(5단계)와 Figma 플러그인(6단계)은 아직 없다.

## 구조: 서버 없는 정적 웹 앱
- **웹 앱**(GitHub Pages): 화면과 에이전트 로직이 모두 브라우저에서 돈다.
- **데이터**: 케이스(질문지 답, 브리프, 승인 기록)는 사용자 PC에만 저장한다. 브라우저 저장소(IndexedDB) 또는 Chrome·Edge에서 고른 PC 폴더.
- **키**: API 키·연결 코드·토큰은 사용자 브라우저에만 저장한다. 원하면 비밀번호로 암호화한다.
- **LLM 연결**(설정 화면에서 선택)
  - 일반 사용자: 본인의 API 키 — Anthropic(Claude), OpenAI, Google Gemini 중 선택. 브라우저가 각 회사 API를 직접 호출한다. 모델은 "연결 확인"으로 받은 목록에서 고른다.
  - Claude Code 사용자: 이 PC에서 [브리지](bridge/bridge.mjs)를 실행해 Claude CLI로 생성한다.
- 모델에는 상호와 질문지 답만 보내고 담당자 이름·연락처는 보내지 않는다.

## 사용
1. 설정에서 LLM 연결 (API 키 입력 → 연결 확인 → 모델 선택, 또는 브리지 실행 후 연결 코드 입력)
2. 질문지: 담당자가 직접 입력하거나, 광고주에게 `#/intake?mode=client` 링크를 보내 답변 파일을 받아 "케이스 > 광고주 답변 파일 가져오기"
3. 케이스에서 브리프·아이디어 생성 → 확정 항목 처리 → 아이디어 선택 → 게이트 1 승인
4. 이미지: 사진·로고 올리기 → 프롬프트 만들기(Figma에 붙여 넣기) → Figma 프레임 링크로 가져오기 또는 직접 올리기 → 제품 누끼 → 검수 체크 → 고르기 → 이미지 확정 (Figma 토큰은 설정에서)
5. 합성: 시안 A/B 미리보기(사이즈 3종) → 문구·버튼 색·제품 위치·로고 위치 조정 → 점검 통과 → PNG 6장 저장
6. 검수: "검수 실행"(규칙 + 이미지, LLM 비용 있음) 또는 "규칙만 검사" → 오류는 고치거나 사유 적고 넘기기 → 사람 확인 체크 → 게이트 2 승인
7. 광고주 확인: "시안 확인 파일"을 내려받아 `#/proof` 주소와 함께 광고주에게 보냄 → 광고주가 확정하거나 수정 요청한 답변 파일을 "광고주 답변 파일 가져오기" (수정 요청이면 합성·이미지 단계로 돌아가 다시 검수)
8. 납품: (심의 업종이면 완성본 심의 결과 기록 후) "납품 ZIP 내려받기"
9. 다른 사람·PC로 넘길 때는 "케이스 파일 내보내기/가져오기"

## Claude CLI 브리지
Claude Code가 설치·로그인된 PC에서 (Node 18 이상, 의존성 없음):
```bash
node bridge/bridge.mjs
```
- 화면에 나오는 주소와 **연결 코드**를 웹 앱 설정에 넣는다. 코드는 `~/.ad-agent-bridge.json`에 저장된다 (`--new-code`로 새로 만들기).
- 127.0.0.1에서만 열리고, 허용된 웹 주소에서 온 요청만 받는다. 다른 주소에서 쓰려면 `--origin https://...`.
- 하는 일은 `claude -p --json-schema` 구조화 생성 하나뿐이다(도구 없음). 검수 때는 시안 이미지도 함께 넘긴다(0.2.0부터). 프롬프트와 이미지는 기록하지 않는다.

## 개발
```bash
npm install
npm run dev        # http://localhost:5173
npm run dev:fake   # 가짜 모델로 화면만 시험 (키 불필요)
npm test           # API 호출 없는 테스트
npm run build      # dist/ (배포본에는 CSP가 들어간다)
```
배포: `main`에 푸시하면 [GitHub Actions](.github/workflows/pages.yml)가 테스트·빌드 후 Pages에 올린다.

## 코드 구조
| 경로 | 내용 |
|---|---|
| `.claude/skills/` | 스킬 = 프롬프트의 단일 원본. 빌드에 텍스트로 들어간다 |
| `src/core/` | 질문지 스키마, 브리프·아이디어 생성 결과 검증과 태그 부착, 케이스 서비스(게이트·잠금·내보내기) |
| `src/llm/` | 생성기(Anthropic·OpenAI·Gemini API, 브리지, 가짜), JSON 스키마 변환, 검증 실패 시 1회 재생성 파이프라인 |
| `src/core/images.ts`, `imageService.ts` | 이미지 경로(ad-image-router), 검수 기준, 프롬프트 검사, 이미지 저장·기록·확정 |
| `src/core/compose.ts`, `composeService.ts`, `src/render/` | 합성 명세·템플릿 배치·한글 줄바꿈·점검, 캔버스 렌더러, Pretendard 폰트 |
| `src/integrations/` | Figma 프레임 PNG 가져오기, 브라우저 누끼(Transformers.js) |
| `src/storage/` | 케이스 저장소(IndexedDB / PC 폴더 / 메모리), 설정·비밀값 저장과 암호화 |
| `src/ui/` | 화면 (홈, 질문지, 케이스, 케이스 상세, 설정) |
| `bridge/bridge.mjs` | Claude CLI 브리지 (로컬 실행, 배포본에 포함되지 않음) |
| `config/settings.json` | 기본값과 미정 항목 |

## 규칙을 지키는 방법
- 모델은 JSON 스키마로만 답하고, 출처 태그와 `[추정]`은 코드가 붙인다. "모르겠음" 질문에서 나온 항목은 모델이 빠뜨려도 `[추정]`이 붙는다.
- 1부 3번 답이 있으면 목적은 그 값으로 고정한다. 근거는 1부 6번에 글자 그대로 있는 문구만 남긴다.
- 검증 오류(지어낸 숫자, 금지어, "모두" 타깃, 이미지 속 글자·로고 등)가 있으면 1회 다시 생성하고, 그래도 남으면 "사람이 확정할 항목"에 올린다.
- 게이트 1은 확정 항목이 모두 처리되고 아이디어 1안이 선택되어야 통과한다. 승인 후에는 브리프·아이디어를 바꿀 수 없다.
